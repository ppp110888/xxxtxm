## Docker 部署验证

### 环境堆栈
```
docker compose up -d  →  MySQL (3307)  +  Redis (6379)  +  RabbitMQ (5672)  +  Go-Judge (5050)
                                 │              │               │                  │
                                 ▼              ▼               ▼                  ▼
                          DruidDataSource   Sa-Token      RabbitMQConfig    GoJudgeClient
                          (Druid 连接池)   (Redis 存 Token)  (AMQP 就绪)      (HTTP 沙箱)
```

### 启动方式
```bash
# 1. 启动所有中间件
docker compose up -d
# 2. 启动后端 (默认 profile 连接 Docker 中的 MySQL/Redis/RabbitMQ)
cd backend && mvn spring-boot:run
# 3. 启动前端
cd frontend && pnpm dev
```

### 开发模式（零 Docker，H2 嵌入式数据库）
```bash
cd backend && mvn spring-boot:run -Dspring-boot.run.profiles=dev
cd frontend && pnpm dev
```

### 镜像拉取（国内网络）
```bash
# Docker Hub 不可达时，通过代理拉取
docker pull docker.1ms.run/library/mysql:8.0
docker tag docker.1ms.run/library/mysql:8.0 mysql:8.0
# 其他镜像同理：redis:7.2-alpine、rabbitmq:3.12-management-alpine、criyle/go-judge:latest
```

## 关键技术实现

### 阶段三：AI 私教赋能架构
```
IDE 提交失败 ──→ JudgeService.judge()
                      │
                      │ non-AC 触发
                      ▼
               CompletableFuture.runAsync()
                      │
                      ▼
               AiService.diagnoseSync()  ←── Prompt 工程
                      │
            ┌─────────┴─────────┐
            ▼                   ▼
    AiModelClient.chat()  AiModelClient.chatStream()
    (同步，判题后保存)     (SSE 流式，前端 EventSource)
                                  │
                                  ▼
                          AiController.diagnose()
                          GET /student/ai/diagnose/{id}
                          (SSE → SseEmitter 推送)
                                  │
                                  ▼
                          前端 useAiStream composable
                          (打字机效果 + Markdown 渲染)
```

### AI 功能清单

| 功能 | 触发方式 | 交互模式 | 前端展示 |
|------|----------|----------|----------|
| **代码纠错诊断** | 判题失败自动触发（异步） | 同步 API → 保存到 errorMessage | IDE 输出面板 |
| **实时 AI 诊断** | IDE 输出面板「🤖 AI 诊断」按钮 | SSE 流式（EventSource） | AI 诊断面板（打字机） |
| **学情报告** | GrowthCenter「生成诊断报告」按钮 | SSE 流式（EventSource） | 报告卡片（Markdown） |

### AI 模型接入
```
配置: codemate.ai.api-url=https://api.deepseek.com/v1
      codemate.ai.model=deepseek-chat
      API Key: 环境变量 AI_API_KEY（不写入配置文件）

Prompt 设计:
  - SYSTEM_DIAGNOSIS: 耐心编程导师，分析错误 + 修复建议 + 知识点补充 + 鼓励
  - SYSTEM_REPORT: 教育分析师，薄弱点诊断 + 错误分类 + 学习建议

响应格式: Markdown（代码块 ``` 包裹 + 结构化标题）
未配置 AI_API_KEY 时自动降级显示提示信息
```

### 阶段二：判题引擎架构
```
POST /api/v1/student/submit          POST /api/v1/student/run
         │                                      │
         ▼                                      ▼
  SubmissionService.submit()              JudgeService.run()
         │                                      │
    [dev] ├── JudgeService.judge(id) ──────────┤
    [prod]├── RabbitMQ ──► JudgeConsumer ──────┤
         │                                      │
         ▼                                      ▼
  DevJudgeService / GoJudgeClient        ProcessBuilder / Go-Judge
  (ProcessBuilder / HTTP)                (编译 → 运行 → 收集输出)
         │                                      │
         ▼                                      ▼
  比对 stdout vs 预期输出                 直接返回 stdout/stderr
         │
         ▼
  WebSocket → 前端实时展示结果
```
